# SynapseQA: Neuro-Symbolic Reasoner

SynapseQA is a hybrid QA demonstration that combines neural candidate generation with symbolic checks. Candidate answers are generated by a neural model (Gemini API or local fallback), checked against an RDFLib RDF Knowledge Graph (demo fact base), and validated with SPARQL 1.1 queries before output delivery. The symbolic layer is intended to detect contradictions and ground retries; it is not presented as a guaranteed accuracy improvement over retrieval alone.

## Key Features
- **Neural Candidate Generation**: Gemini API or fallback engine generates initial answers from contextual prompts.
- **Symbolic Verification**: Stores entity-relation fact triples inside an in-memory RDFLib RDF Graph (24 hand-coded demo facts for testing/demonstration).
- **Logical Rules Checking**: Parses statements to detect subject-predicate-object semantic edges, validating them against verified facts.
- **Automatic Retry Loop**: Detects contradictions, feeds verified facts back into context, and triggers grounded re-generation when validation fails.
- **MLflow Experiment Tracking**: Tracks accuracy across pipeline configurations using computed KG evaluation metrics instead of hardcoded benchmarks.
- **Immersive Void Terminal UI**: A futuristic dark dashboard with a rotating 3D network node constellation, typewriter reasoning traces, and comparison tools.

## Architecture Flow

```
                         [ User Question ]
                                │
                      ┌─────────▼─────────┐
                      │    Neural LLM     │ (neural candidate generation)
                      └─────────┬─────────┘
                                │
                      ┌─────────▼─────────┐
                      │  Symbolic Check   │ (SPARQL constraint check)
                      └─────────┬─────────┘
                                │
                 ┌──────────────┴──────────────┐
                 ▼                             ▼
        [ Contradiction? ]               [ Verified? ]
                 │                             │
        ┌────────▼────────┐                    │
        │  LLM + Feedback Loop  │                    │
        │ (Inject Facts)  │                    │
        └────────┬────────┘                    │
                 │                             │
        ┌────────▼────────┐                    │
        │  Corrected LLM  │                    │
        └────────┬────────┘                    │
                 │                             │
                 └──────────────┬──────────────┘
                                │
                      ┌─────────▼─────────┐
                      │ Grounded Output   │ (Bilingual verified answer)
                      └───────────────────┘
```

## Accuracy Benchmarks

These metrics are computed at runtime from a 32-example track: 24 clean fact questions plus 8 deterministic noisy-retrieval cases. Benchmark mode uses the local mock and does not call Gemini even when an API key is configured. The noisy track gives retrieval incorrect facts for a subset; symbolic validation grounds those cases back to the canonical KG facts.

| Configuration | F1-Score (last run) | Hallucinations |
| :--- | :---: | :---: |
| **LLM Alone** | 13.0% | High |
| **LLM + KG Retrieval** | 92.1% | Moderate |
| **LLM + KG + Symbolic (SynapseQA)** | 98.3% | **Contradictions Checked** |

Numbers are from an actual run on the 24-fact demo dataset plus the 8-case noisy track, not hardcoded; reproduce with `python -m pipeline.experiments` or hit `/api/benchmark` for live numbers.

## Quick Start (Local Run)

### 1. Installation
Clone the repository and install requirements:
```powershell
pip install -r requirements.txt
```

### 2. Configure API Keys (Optional)
If you want to use the live Gemini LLM candidate generator (otherwise, the system falls back onto a local knowledge graph resolver automatically):
```powershell
# Windows PowerShell
$env:GEMINI_API_KEY="your-gemini-api-key-here"
```

### 3. Run Server
Launch the FastAPI uvicorn daemon:
```powershell
python -m uvicorn api.app:app --reload
```
Open your browser and visit: **`http://127.0.0.1:8000`**

### 4. Running Automated Tests
Run integration and routing tests:
```powershell
pytest tests/
```

## Deployment (Render with Docker)
This project is configured with a size-optimized Dockerfile installing CPU-only PyTorch, making it compatible with cloud platforms like Render.

1. Commit your changes and push your repository to GitHub.
2. Log into **Render** and create a **Web Service**.
3. Choose **Docker** as your environment.
4. Render will compile the container and provide your live public URL!
